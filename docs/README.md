### [`WAF拦截与弹窗死循环分析及规避指南.md`](WAF拦截与弹窗死循环分析及规避指南.md) — WAF / 验证

核心结论：

- 常规书源 `loginCheckJs` 保持为空，交给阅读底层 OkHttp/Cloudflare 拦截器处理。
- 严禁用 `indexOf("waf")`、`indexOf("验证")` 之类全局模糊匹配，否则正常页面也会误判，形成无限弹窗。
- 严禁在校验脚本里用 `java.connect(url)` 二次请求，它会丢失当前请求的 Header/Cookie。
- 不要调用 `java.randomUUID()` 等未注入的方法，用纯 JS 实现。
- 会话 Token 用 `java.getCookie` / `java.putCookie` 持久化。

### [`移动端API与加密书源避坑指南.md`](移动端API与加密书源避坑指南.md) — API / 加密

核心结论：

- 全局 `header` 要完整带上动态鉴权参数，否则第一次请求就 401。
- `JSON.parse(cache.get(...) || '{}') || {...}` 是错误写法：`{}` 在 JS 里是真值，默认 Header 不会执行。
- 变量初始化有时序问题，域名要兜底，防止拼出 `undefined/xxx`。
- 搜索词只做 `trim()` + `encodeURIComponent`，不要用正则截断空格后的内容。
- 优先复用搜索请求的响应做本地解密，失败再发网络请求。

### [`禁漫天堂与高防漫画站书源实战避坑指南.md`](禁漫天堂与高防漫画站书源实战避坑指南.md) — 漫画 / 高防

核心结论：

- `bookUrlPattern` 要精准，不能包含 `search` / `albums` 等列表路径。
- `webJs` 不要为空轮询，否则白屏/超时；优先用 `,{"webView":true}`。
- 详情页即目录时，`ruleBookInfo.tocUrl` 留空，复用 `tocHtml`。
- 图片切片、混淆、解密要在规则里明确处理，不能假设 `img@src` 可用。
- 高防站的验证逻辑要收敛，避免每个请求都触发验证。

## 新增文档的写法

1. 文件名：`站点或主题_问题_修复.md`，例如 `某某网_搜索404_修复.md`；
   合并多个单站案例时用 `案例-<站点A>与<站点B>.md`。
2. 结构固定：**现象 → 根因 → 修复 → 可推广的经验**。
3. 只写有复用价值的内容；一次性的调试输出放 `temp/`，不要提交。
4. 修完后在 [`BUG_FIXES.md`](BUG_FIXES.md) 加一行摘要并链接到新文档。
5. 如果内容与现有专题重复，**优先补进专题**，不要再新建一份平行文档。
